# macOS Desktop Connector Implementation Plan

**Goal:** 给既有 IM gateway 增加Mac桌面接入，保持Linux云端服务与桌面连接器分离。

**Approach:** 不运行来源未审计的机器人库；新增小型原生辅助功能驱动，Python负责轮询、基线、增量识别和既有HTTP bridge投递。不通过协议破解、全盘聊天数据库、OCR或云端模型猜测收发方向。界面信息不足时明确停止。用户仅授权文件传输助手自测；其他联系人不自动监听/发送。

**Platform boundary:** 后端 Docker 在Linux运行，桌面连接器通过HTTPS连接。Mac驱动在有登录GUI的Mac运行。Linux云端不等于Linux微信GUI；本轮补Linux部署验证和驱动接口说明，未验证的Linux客户端自动收发不得标成已支持。

- [ ] 先测试首轮历史基线不处理、自己消息过滤、重复同文消息增量、窗口变化/历史滚动拒绝、重启基线、异常发送不重试。
- [ ] 抽桌面驱动协议和轮询逻辑，复用DesktopBridge鉴权与出站持久记录。
- [ ] Mac原生helper：只访问确切WeChat bundle；需辅助功能权限；只读取指定会话；发送前重验当前会话/进程/消息快照及空草稿，确认结果。
- [ ] 默认doctor/observe不发送；run须显式--send及联系人配置，当前仅文件传输助手自测。不暴露聊天内容日志。
- [ ] 编译原生helper及模拟测试；本机用CUA验证指定会话，无法获得可可靠读取结构则明确记录阻塞，不使用盲点坐标发送替代驱动验证。
- [ ] 全套测试/代码review，提交远端main，再从干净对应源码构建并验证发布；不购买资源、不调用付费转链。

## 执行裁决

- 用户明确选择暂不做OCR；本机微信4.2.0辅助功能树不完整。
- 辅助功能显示名不能证明文件传输助手特殊身份；首版Mac改为只读doctor/observe，移除发送实现及CLI发送入口。未验证身份不得向后端提交消息。
- 历史部分加载不能与新追加可靠区分；共享self-test轮询增加每次运行独立测试码，不作普通聊天exactly-once承诺。
- Linux云端后端不需改动或重新部署；本轮只做Linux运行环境兼容性验证。Linux微信GUI驱动未验证，不宣称已支持。
